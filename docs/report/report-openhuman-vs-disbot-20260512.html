결정 요지
OpenHuman은 운영 단계(v0.53.29)의 크로스 플랫폼 데스크톱 에이전트로 멀티 채널·메모리·OAuth 통합·관측 인프라가 이미 갖춰져 있습니다. DisBot은 보안 우선 설계와 위협 모델 문서화가 강점이지만, 인터페이스 정의만 완료된 알파/베타 단계입니다. OpenHuman을 아키텍처 기반으로 채택하고, DisBot의 보안·감사·비용 통제 설계를 신규 도메인 모듈로 이식하는 것이 ROI가 가장 높은 경로입니다.
한 줄 결론
OpenHuman을 base로, DisBot을 security·audit·cost 도메인 자료원으로 — 두 프로젝트의 강점을 양방향이 아닌 단방향 흡수로 결합합니다.
Section 02 · Project Overview

프로젝트 개요

각 프로젝트의 정체성, 스택, 성숙도, 타깃 사용자를 정의합니다.

Project A

OpenHuman

Rust 코어 + React/TS + Tauri v2 데스크톱 앱. 메모리 우선(memory-first) 통합 AI 에이전트 플랫폼.

  • 스택: Rust · TypeScript · Tauri v2 (CEF)
  • 버전: v0.53.29 (활발한 운영)
  • 플랫폼: Windows · macOS · Linux
  • 채널: Telegram, Discord, Slack, WhatsApp, iMessage, Matrix 등 7+
  • OAuth: 118+ 커넥터
  • 메모리: SQLite + 트리 요약 + Obsidian export
  • 관측: Sentry · OpenTelemetry · Prometheus
Project B

DisBot

Python 기반 Windows 단일 사용자 Claude/Ollama 디스코드 봇. 보안 우선 설계.

  • 스택: Python 3.10+ · Node.js(Claude Code CLI)
  • 단계: Alpha/Beta (설계 우수, 구현 부분 완료)
  • 플랫폼: Windows 전용 (서비스/트레이/DPAPI)
  • 채널: Discord 주력 · Telegram/Slack 예정
  • LLM: Claude CLI subprocess + Ollama 폴백
  • 보안: 5계층 방어 + 플러그인 deny-all 권한제
  • 특징: OpenClaw CVE 학습 위협 모델 문서화
Why the gap matters
OpenHuman은 "운영 중인 제품", DisBot은 "설계 단계의 보안 봇"입니다. 두 프로젝트는 규모·완성도·타깃이 본질적으로 다르므로 동등 비교가 아닌 "기반과 자료원"의 비대칭 통합이 합리적입니다.

Section 06 · Decision

기준 프로젝트 결정

통합 에이전트(Unified Agent)의 아키텍처 기반을 선택하는 의사결정 근거입니다.

결정
OpenHuman을 통합 에이전트의 기반(architectural base)으로 채택합니다. DisBot은 보안·감사·비용 통제·플러그인 샌드박스 설계의 자료원(source-of-design)으로 활용합니다.

결정의 5가지 근거

# 근거 구체 내용
1 어려운 부분이 구현 완료 멀티 플랫폼, 멀티 채널, 메모리 트리, OAuth 118+, JSON-RPC 디스패치, MCP 클라이언트, 자동 업데이터가 운영 단계로 갖춰져 있어 DisBot 위에 처음부터 쌓는 비용을 회피할 수 있습니다.
2 DisBot은 인터페이스 정의 단계 gateway.py·트레이·서비스 모듈이 스텁 상태, 웹 대시보드는 의존성만 선언. 기반으로 삼으면 사실상 새로 만드는 비용 발생.
3 강점이 단방향 이식 가능 DisBot 강점은 "설계·문서·작은 모듈" — OpenHuman 도메인 디렉터리에 src/openhuman/security/ 형태로 추가하기 용이.
4 플랫폼 흡수 비대칭 Windows-native(DPAPI/트레이/서비스)는 OpenHuman Tauri 셸이 이미 커버하거나 모듈 추가가 쉬움. 반대로 OpenHuman → DisBot은 macOS/Linux를 새로 짜야 함.
5 단일 사용자 제약은 통합 에이전트 목표와 충돌 DisBot은 보안 단순화를 위해 단일 사용자 모델을 의도적으로 채택했으나, 통합 에이전트는 다채널·다계정·팀 단위 사용 전제. OpenHuman 모델이 목표에 부합.
Section 07 · Roadmap

통합 로드맵

OpenHuman 기반 위에 DisBot 강점을 단계적으로 이식하는 5단계 실행 계획입니다.

Phase 01

보안·감사 도메인 이식

src/openhuman/security/ 신규 도메인 추가. prompt_injection_guard.rs, audit/(JSONL pre/post 로깅), cost_guard.rs(예산 한도). 컨트롤러 스키마는 src/openhuman/security/schemas.rs에 정의 후 src/core/all.rs 와이어업.

Phase 02

스킬 샌드박스 강화

DisBot PluginSandbox의 권한제·코드 스캐너를 OpenHuman 스킬 시스템에 맵핑. src/openhuman/skills/permissions.rs(deny-all 디폴트), integrity.rs(SHA-256 매니페스트). WDIO E2E로 권한 거부 시나리오 검증.

Phase 03

Discord 채널 보강

OpenHuman src/openhuman/channels/discord/에 슬래시 명령 표준화·첨부 파이프라인 보강. DisBot의 Claude CLI subprocess 방식은 채택하지 않고 compatible.rs HTTP 경로 사용.

Phase 04

비용·요금제 UI

app/src/components/settings/에 일·주·월 누적 비용 대시보드, 한도 게이지, 경고 토스트 추가. 데이터 소스는 Phase 1의 cost_guard RPC.

Phase 05

위협 모델 문서화

gitbooks/developing/security.md 신설 — DisBot ANALYSIS.md의 위협 매트릭스를 OpenHuman 컨텍스트로 재작성. SECURITY.md 업데이트, 침해 보고 채널 명시.

도메인 추가 코드 스케치 (CLAUDE.md 규칙 준수)

// src/openhuman/security/mod.rs
pub mod audit;
pub mod cost_guard;
pub mod prompt_injection_guard;
pub mod permissions;
pub mod schemas;

pub use schemas::{
    all_controller_schemas as all_security_controller_schemas,
    all_registered_controllers as all_security_registered_controllers,
};
결과 기대치
Phase 1–2 완료 시 통합 에이전트는 OpenHuman의 운영 안정성 + DisBot의 보안 명시성을 동시에 확보합니다. Phase 3–4는 사용자 가시 가치(비용 예측 가능성), Phase 5는 거버넌스·감사 대응(컴플라이언스)에 기여합니다.
Section 08 · Exclusions

배제 항목과 리스크

통합 시 의도적으로 채택하지 않을 DisBot 요소와, 예상되는 통합 리스크입니다.

DisBot에서 채택하지 않을 것

항목배제 사유
Claude Code CLI subprocess 호출지연·CLI 버전 결합·스트리밍 부재. OpenHuman compatible.rs HTTP 경로가 우수.
단일 사용자 가정통합 에이전트는 다계정·다채널·팀 단위 사용 전제.
파일 전용 영속화(JSONL 한정)OpenHuman SQLite + 메모리 트리가 이미 우월. 감사 로그만 JSONL로 보조 사용.
Python 런타임코어가 Rust인데 Python 추가 시 배포·보안 표면 확대.
FastAPI 웹 대시보드OpenHuman은 Tauri 데스크톱 UI가 표준.

통합 리스크

Risk · 도메인 비대화
OpenHuman 코어는 이미 1,068 파일 규모. security 도메인 추가가 또 다른 무게로 작용할 수 있습니다. 완화책: 각 보안 컴포넌트를 단일 책임으로 분리하고, mod.rs는 light export만 유지합니다(CLAUDE.md 규칙).
Risk · 비용 가드 UX 충돌
OpenHuman 사용자는 비용 한도 알림에 익숙하지 않을 수 있습니다. 완화책: opt-in으로 시작하고, 예산 설정 시에만 가드가 활성화되도록 설계합니다.
Risk · 보안 문서 노후화
DisBot의 위협 매트릭스는 2024–2025년 CVE 기반. OpenHuman 컨텍스트(CEF 웹뷰 스캐너, OAuth 토큰 관리)는 위협 표면이 다릅니다. 완화책: 단순 이식이 아닌 재작성하며, Tauri/CEF 특유 위협(JS 인젝션, IPC 권한)에 맞춰 갱신합니다.
Section 09 · Conclusion

결론

통합 에이전트 구축을 위한 최종 권장 사항입니다.

최종 권장
OpenHuman을 통합 에이전트의 기준(architectural base)으로 채택하고, DisBot은 보안·감사·비용 통제·플러그인 샌드박스 설계의 자료원으로 사용합니다. OpenHuman은 멀티 플랫폼·멀티 채널·메모리·OAuth·관측 인프라가 운영 단계로 완비되어 통합 에이전트의 80%를 이미 충족하며, DisBot의 핵심 가치(위협 모델·플러그인 권한제·비용 한도·감사 로그)는 신규 도메인 src/openhuman/security/로 이식하는 것이 ROI가 가장 높습니다.

실행 우선순위

  • 즉시: Phase 1(보안·감사 도메인) 착수 — 통합 에이전트의 신뢰성 기반
  • 3개월: Phase 2(스킬 샌드박스 강화) + Phase 5(위협 모델 문서화)
  • 6개월: Phase 3(Discord 채널 보강) + Phase 4(비용 UI)
한 줄로
"이미 완성된 운영 플랫폼 위에 검증된 보안 설계를 단방향 흡수한다" — 이것이 두 프로젝트의 비대칭적 강점을 합치는 가장 효율적인 경로입니다.
